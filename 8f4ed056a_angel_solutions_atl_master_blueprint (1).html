1. System Overview

This system replaces Angel Solutions ATL's ManyChat automation with a custom pipeline: Meta (Instagram + Facebook) comments/DMs are read via Graph API, classified and drafted by an LLM (Cloudflare Workers AI, Llama 3.1 8B), checked against compliance rules, and synced to GoHighLevel as the CRM. It currently runs in shadow mode — every action is drafted, logged, and held for human review rather than actually delivered, gated by ClientComplianceLaunch.launch_approval_status.

Stack: Base44 backend functions (Deno/TypeScript) · Cloudflare Workers AI (LLM) · Meta Graph API (Instagram + Facebook) · GoHighLevel API (CRM + SMS) · Base44 entities (data layer) · Base44 scheduled automations (cron triggers).

Client identifier: all data is scoped by intake_id = "6a46c0696b95e7dc9dd6251c" (Angel Solutions ATL). This is currently hardcoded per client — see Backlog §9.4 for the multi-tenant gap.

4. Backend Functions
4.1 angelEngageCycle

Trigger: scheduled automation "Angel Solutions ATL Engagement Monitor" (Instagram token passed in via get_connector_token → payload each run).

Does: polls Instagram (last 5 posts' comments + last 20 DM threads) and Facebook (same) via Graph API GETs. Runs classifyComment/classifyAndExtractDm (Cloudflare AI) on new items, applies compliance + link checks, upserts Lead/Conversation/CommentLog, syncs GHL contact, sends escalation SMS when triggered.

Known limitation: read-only against Meta — never calls Meta's send-message or hide-comment endpoints (see Backlog §9.1).

4.2 facebookWebhookReceiver

Trigger: real-time Meta webhook (GET for verification handshake using VERIFY_TOKEN, POST for actual events).

Does: same classify/draft/log pipeline as angelEngageCycle but event-driven instead of polled, for Facebook comments and Messenger DMs only. No Instagram equivalent exists yet.

Verify before launch: confirm the webhook subscription is actually registered and active in the Meta App dashboard, not just deployed here.

4.3 angelFollowUpCycle

Trigger: scheduled automation "Angel Solutions ATL Follow-Up Nurture Sequence," daily at 8am Jordynn's time (1pm UTC).

Does: for every non-terminal, non-paused Lead, checks days since last_contact_at against the 7-step day offsets [1,3,5,8,12,16,18]. Steps 1/2/7 use fixed templates from ClientAutomationRules; steps 3-6 are AI-generated variants (Cloudflare) using a specific angle per step. Logs to FollowUpStep and Conversation.

Known limitation: does not check Meta's 24-hour messaging window or use message tags — and doesn't call any send API yet either (see Backlog §9.1, §9.2).

7. Compliance Logic

Banned phrase filter (checkCompliance()): word-boundary regex against ['credit sweep','guarantee','guaranteed','best','yo','bet']. Runs on every generated reply before it's logged/sent.

Link enforcement (stripUnapprovedLinks()): regex-matches URLs in generated text, strips anything not in the active ApprovedLink list.

AI disclosure: prepended to the first bot message in a new conversation when ClientComplianceLaunch.require_ai_disclosure_dms is true.

Shadow mode gate: shadowMode = compliance.launch_approval_status !== 'approved', checked at the top of every function run.
